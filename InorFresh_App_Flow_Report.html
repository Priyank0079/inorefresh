1. What is InorFresh?

The Big Picture

Simple Explanation

InorFresh is an online fresh fish & seafood delivery platform — like Blinkit or Zepto but specialised for fresh fish, seafood, and related products. Customers order from their phone, local sellers pack the order, and a delivery rider delivers it in as little as 10 minutes. The platform also supports B2B bulk fish trade between port sellers and business buyers.

5. Seller / Warehouse Module

How Sellers Manage Their Business

What is a Warehouse/Seller?

A "Warehouse" in InorFresh is a local fish shop or seafood supplier. Each seller has a physical location. The platform uses GPS to match a customer's location to nearby sellers — so only relevant products appear to the customer. Sellers set their own product list, prices, and inventory.

📦 Product Management

  • Add new products with photos, price, MRP, and description
  • Create product variations (e.g. 500g / 1kg / 2kg packs)
  • Set stock quantity — auto goes out-of-stock when 0
  • Mark products as active or inactive
  • Products need Admin approval before going live
  • View all products with status (Active / Pending / Rejected)
  • Inward stock management — log new stock arrivals

📊 Seller Dashboard & Reports

  • Today's orders count & revenue
  • Pending / Processing / Delivered order counts
  • Monthly revenue graph
  • Top selling products
  • Wallet balance (money earned)
  • Withdrawal request to Admin
  • Commission history per order
  • Download reports (PDF / CSV)

📍 Location-Based Matching — How It Works

Step 1 – Seller Sets Service Area

Admin assigns each seller a service radius in KM (e.g. 5 km). The seller's GPS coordinates are stored.

Step 2 – Customer Opens App

Customer's GPS coordinates are captured. The system finds all sellers within radius.

Step 3 – Products Filtered

Only products from nearby sellers are shown. Customer never sees out-of-area products.

9. Complete Order Lifecycle

From "Place Order" to "Delivered" — Every Status Explained

Order Status Timeline

1

Received

Customer places the order. Payment is processed. Seller gets a notification immediately.

2

Accepted

Seller reviews and accepts the order. Customer gets a "Your order is accepted" push notification.

3

Processed / Packed

Seller packs the items and marks order as ready for pickup.

4

Picked Up

Delivery boy picks up from seller. Customer can see rider is on the way.

5

On the Way / Out for Delivery

Rider is heading to the customer. Live map tracking is active.

6

Delivered

Rider enters the customer's OTP at the door. Order marked as delivered. Wallet & commission updated.

✕

Cancelled / Rejected

If seller rejects or customer cancels before pickup, the payment is refunded to customer's wallet.

🔢 OTP Delivery System

  • Every customer has a permanent 4-digit delivery OTP stored in their account
  • Rider sees the OTP on their app at time of delivery
  • Customer tells the rider their OTP
  • Rider enters it — order marked as Delivered
  • This prevents fake delivery claims and protects both customer and rider
  • Rider cannot mark delivered without correct OTP

💳 Payment Methods

  • Online Payment — via Razorpay (UPI, Cards, Net Banking)
  • Cash on Delivery (COD) — customer pays rider in cash at door
  • Wallet — use wallet balance (received from refunds or credits)
  • Wallet + Online — partial payment from wallet, rest online
  • Coupon code discount applied at checkout
  • Invoice generated after every delivery

👛 Wallet System

  • Customer wallet — Refunds go here; can be used to pay for orders
  • Seller wallet — Commission from each delivered order credited here; withdraw to bank via admin
  • Delivery boy wallet — Per-delivery earnings; withdraw to bank via admin
  • Platform wallet — Platform fee and delivery charge held here; admin controls payouts
  • Every wallet transaction (credit/debit) is logged with opening and closing balance

📊 Commission Structure

  • Individual sellers can have a different rate (override)
  • Delivery boys have their own commission rate per delivery
  • Commission is calculated automatically when order is Delivered
  • Admin can view all commissions earned per order
  • Withdrawal requests from sellers/riders require Admin approval

12. Notifications System

How Everyone Stays Updated in Real-Time

Three Types of Notification Delivery

🔔 Push Notification (FCM)

Sent to mobile/browser even when the app is closed. Uses Firebase Cloud Messaging. Appears as a system notification on the phone.

⚡ Real-Time (Socket.IO)

Instant in-app alerts while the app is open. When a new order arrives, the seller hears a sound and sees it immediately without refreshing.

📋 In-App Notification Inbox

All notifications are stored and can be read from the Notifications page. Shows read/unread count with a badge.

13. Flutter Mobile App

How the Mobile App Works

What is the Flutter App?

The mobile app is built with Flutter — Google's framework for building Android and iOS apps. It wraps the InorFresh React web app inside a WebView (like a powerful in-app browser), so both the website and app share the same codebase and features. The Flutter layer adds native features like system push notifications, camera access, and app store distribution.

Why This Approach?

Building one web app + wrapping it in Flutter means the team only maintains one codebase for web + Android + iOS. Any updates go live on all platforms simultaneously. No separate mobile app code to maintain.

Flutter App Features (Native Layer)

Native Push Notifications
  • Uses native Firebase SDK
  • Notifications appear in Android/iOS system tray
  • Work even when app is fully closed
  • Tapping opens the relevant screen
App Store Distribution
  • Published on Google Play Store
  • Can be published on Apple App Store
  • Users install like any normal app
  • Auto-update support
Location Access
  • Requests device GPS permission
  • Passes location to web app
  • Used for seller matching
Performance
  • App-shell caching (loads instantly)
  • Offline fallback page
  • Images cached locally
  • Smooth transitions

14. Security & Authentication

How the App Keeps Data Safe

Security Measures

  • JWT Tokens — All API calls require a valid login token that expires and is refreshed
  • OTP Verification — Phone number verified via SMS OTP at registration and key actions
  • Role-Based Access — Each user type (Customer, Seller, Rider, Admin) can only access their own data and actions
  • Delivery OTP — Prevents fake delivery claims — only customer can confirm delivery
  • Return OTP — Warehouse verifies receipt of returned items via OTP
  • Password Hashing — All passwords stored encrypted (bcrypt) — never stored plain text
  • HTTPS only — All communication between app and server is encrypted
  • Razorpay — All payments processed by Razorpay (RBI-approved) — InorFresh never stores card details
  • FCM Token dedup — Push notification tokens are cleaned per device when users switch accounts
  • Input Validation — All inputs validated on backend to prevent injection attacks
